Item 1 — Escolha e Preparação da Base de Dados
Mínimo 100.000 registros — sem isso o case não é avaliado
+

A base deve ter contexto de e-commerce. As três sugestões seguras do case são:

  • NYC Taxi Data — dados de corridas de táxi (volume enorme, série temporal rica). Disponível no site oficial da NYC e no BigQuery público.
  • Microsoft AdventureWorks — banco de dados de uma empresa fictícia de vendas. Bom para modelagem dimensional (Kimball).
  • Base de Produtos com Descrições (Amazon) — ideal para o Item 5 (LLM Features). Disponível no Hugging Face. ~3GB, perfeito para o case.
⚠️ CRÍTICO: Base com menos de 100.000 registros = case não avaliado. Verifique o volume ANTES de começar a integrar.
  1. Recomendação estratégica: Use a Base de Produtos Amazon pois ela se encaixa em TODOS os itens: e-commerce (Item 2), texto desestruturado para LLM (Item 5), categorias para análise (Item 7).
  2. Download: Baixe via Python no Colab: 
    from datasets import load_dataset
ds = load_dataset("McAuley-Lab/Amazon-Reviews-2023", 
                  "raw_meta_Electronics", 
                  trust_remote_code=True)
df = ds['full'].to_pandas()
print(len(df))  # verificar >100k
  3. Alternativa com dados sintéticos: Se preferir controle total, gere com Faker em Python: 
    import pandas as pd

records = []

        'price': round(random.uniform(10, 5000), 2),

        'description': fake.paragraph(nb_sentences=5)

import pandas as pd

df = pd.read_csv('seu_dataset.csv')

    .read_dataframe(df)

Item 5 — Feature Engineering com GenAI/LLMs
Transformar texto desestruturado em features estruturadas
+

Este é o item mais diferencial do case — demonstra capacidade de usar IA para gerar valor a partir de dados não estruturados.

  1. Pegue a coluna de descrição/texto do seu dataset (ex: description ou product_title).
  2. No Colab, instale e configure a OpenAI: 
    !pip install openai
from openai import OpenAI
client = OpenAI(api_key="sua_chave_api")
  3. Crie a função de extração de features: 
    def extract_features(title, description):
    prompt = f"""
Analise o produto abaixo e retorne um JSON com:
- category: categoria principal
- subcategory: subcategoria
- material: material principal (se mencionado)
- key_features: lista de até 5 características
- target_audience: público-alvo
- price_segment: budget/mid/premium
- sentiment: positivo/neutro/negativo

Título: {title}
Descrição: {description[:500]}

Retorne SOMENTE o JSON, sem explicações.
"""
    response = client.chat.completions.create(
        model="gpt-4o-mini",  # mais barato
        messages=[{"role": "user", "content": prompt}],
        response_format={"type": "json_object"}
    )
    return response.choices[0].message.content

# Aplicar em amostra do dataset (ex: 1000 linhas)
import json
df_sample = df.head(1000).copy()
df_sample['llm_features'] = df_sample.apply(
    lambda r: extract_features(r['title'], r['description']), 
    axis=1
)
  4. Expanda o JSON em colunas do DataFrame para análise posterior.
  5. Carregue o dataset enriquecido de volta na Dadosfera como nova tabela (Curated Zone).
⚠️ Custo: GPT-4o-mini custa ~$0.15/1M tokens. Para 1000 descrições de ~200 tokens cada = ~$0.03. Viável. Para o dataset completo de 100k, use batch ou processe só uma amostra representativa.
⭐ Bônus: Use um vídeo ou áudio como input — ex: transcreva um vídeo de produto com Whisper e extraia features do texto transcrito.

Item 6 — Modelagem Dimensional de Dados
Kimball (Star Schema) com 2 visões finais
+

Demonstra conhecimento de Data Warehouse. Kimball (Star Schema) é o padrão mais reconhecido e o mais fácil de justificar para e-commerce.

  1. Escolha e justifique o modelo: Kimball Star Schema é ideal para e-commerce por permitir análise rápida por dimensões (produto, cliente, tempo, categoria).
  2. Projete o Star Schema:
    • Fato: fact_orders — order_id, date_key, product_key, customer_key, quantity, price, revenue
    • Dim_Produto: product_key, name, category, subcategory, material (vindo do LLM)
    • Dim_Cliente: customer_key, segment, region, signup_date
    • Dim_Tempo: date_key, year, quarter, month, week, day_of_week
    • Dim_Categoria: category_key, name, parent_category (das features do LLM)
  3. Crie o diagrama no draw.io (diagrams.net) ou dbdiagram.io. Exporte como PNG.
  4. Implemente em SQL (pode ser no Colab com SQLite ou DuckDB): 
    import duckdb
conn = duckdb.connect()

conn.execute("""
CREATE TABLE dim_produto AS 
SELECT 
  ROW_NUMBER() OVER() as product_key,
  product_id, title as name,
  category, subcategory, material
FROM products_enriched
""")

conn.execute("""
CREATE TABLE fact_orders AS
SELECT 
  o.order_id,
  d.product_key,
  CAST(o.order_date AS DATE) as order_date,
  o.quantity,
  o.price,
  o.quantity * o.price as revenue
FROM orders o
JOIN dim_produto d ON o.product_id = d.product_id
""")
  5. Crie 2 views/visões finais prontas para análise:
    • View 1: Revenue por categoria e mês
    • View 2: Top produtos por volume de vendas
⭐ Bônus: Desenhe o diagrama completo mostrando Landing → Standardized → Curated, com as tabelas mapeadas em cada camada.

import pandas as pd
from openai import OpenAI

st.title("🛒 E-commerce Data Explorer")

@st.cache_data

    return pd.read_csv("data/orders_clean.csv")

st.dataframe(df.head(5))

question = st.text_input("Sua pergunta:")
if question and st.button("Analisar"):
    client = OpenAI(api_key=st.secrets["OPENAI_API_KEY"])
    
    context = f"""
    Você é um analista de dados.
